  "content": "# Architecture Documentation - Portfolio V2.0\n\n## 1. Vue d'ensemble\nCe document décrit l'architecture technique pour la refonte du portfolio. L'objectif est de passer d'une structure monolithique HTML/jQuery (Legacy) à une **Single Page Application (SPA)** moderne, performante et typée.\n\n### Principes Clés (BMAD)\n- **Build**: Utilisation de Vite pour un bundling ultra-rapide.\n- **Modularize**: Séparation stricte entre UI (Components), Logique (Hooks/Services) et Données (JSON/Assets).\n- **Architect**: Pattern \"Feature-based\" pour la scalabilité.\n- **Deploy**: Pipeline CI/CD automatisé et conteneurisation.\n\n---\n\n## 2. Stack Technique\n\n- **Core**: React 18 + TypeScript (Strict Mode).\n- **Build Tool**: Vite.\n- **Styling**: Tailwind CSS (Structure) + Modules SCSS (Effets Néon/Complexes) + Framer Motion (Transitions).\n- **State Management**: React Context (Global UI state) + Custom Hooks (Data fetching).\n- **Routing**: React Router v6 (Remplace le système d'iframes).\n- **Animations**: Canvas API encapsulée dans des classes TS (pour la Grille et les Étoiles).\n\n---\n\n## 3. Arborescence du Projet\n\nLa structure suit une approche **Domain-Driven Design** simplifiée pour le frontend.\n\n```text\n/root\n├── .github/                # Workflows CI/CD (GitHub Actions)\n├── public/                 # Assets statiques (favicons, robots.txt)\n│   └── data/               # Contenu JSON (Source de vérité découpée)\n│       ├── profile.json\n│       ├── projects.json\n│       └── skills.json\n├── src/\n│   ├── assets/             # Images, Fonts, Global CSS\n│   │   ├── fonts/\n│   │   ├── textures/\n│   │   └── styles/         # Variables CSS globales, Reset\n│   │\n│   ├── core/               # Le \"Moteur\" de l'application (Agnostique de l'UI)\n│   │   ├── config/         # Constantes, Env vars\n│   │   ├── services/       # Logique métier pure (DataService, AnimationService)\n│   │   ├── types/          # Interfaces TypeScript partagées (IProject, ISkill)\n│   │   └── utils/          # Helpers (Maths pour canvas, formatters)\n│   │\n│   ├── shared/             # Composants réutilisables (Atomic Design)\n│   │   ├── components/\n│   │   │   ├── atoms/      # Button, NeoLink, Icon\n│   │   │   ├── molecules/  # ProjectCard, SkillBadge\n│   │   │   └── organisms/  # Navbar, Footer\n│   │   └── hooks/          # Hooks génériques (useWindowSize, useTheme)\n│   │\n│   ├── features/           # Modules fonctionnels (Pages/Sections)\n│   │   ├── home/           # Landing page (FlyText, Orbit menu)\n│   │   ├── about/          # Timeline, Bio\n│   │   ├── projects/       # Grid de projets, Filtres\n│   │   ├── search/         # Tech Watch, Matrix effect\n│   │   └── visuals/        # Composants Canvas complexes (Grid, Starfield)\n│   │\n│   ├── layouts/            # Structures de page (MainLayout)\n│   ├── App.tsx             # Point d'entrée, Routing\n│   └── main.tsx            # Montage React\n│\n├── Dockerfile              # Configuration pour conteneurisation\n├── nginx.conf              # Config serveur pour Docker\n├── package.json\n└── tsconfig.json\n```\n\n---\n\n## 4. Interaction Composants - Services\n\nL'architecture sépare strictement la **vue** (React) de la **donnée** (JSON) et de la **logique complexe** (Canvas/Calculs).\n\n### Flux de Données (Data Flow)\n\n1.  **Fichiers JSON** (`/public/data/*.json`) : Contiennent tout le texte et les URLs. Aucune donnée n'est hardcodée dans les composants.\n2.  **DataService** (`src/core/services/DataService.ts`) : Singleton responsable du `fetch` et du typage des réponses.\n3.  **Custom Hooks** (ex: `useProjects`) : Appellent le service et exposent l'état (data, loading, error) aux composants.\n4.  **Composants** : Reçoivent les données via props ou hooks et font le rendu.\n\n**Exemple :**\n```typescript\n// 1. Service (Logique pure)\nclass DataService {\n  async getProjects(): Promise<IProject[]> {\n    const res = await fetch('/data/projects.json');\n    return res.json();\n  }\n}\n\n// 2. Hook (Lien React-Service)\nconst useProjects = () => {\n  const [projects, setProjects] = useState<IProject[]>([]);\n  useEffect(() => {\n    dataService.getProjects().then(setProjects);\n  }, []);\n  return projects;\n};\n\n// 3. Component (Vue pure)\nconst ProjectsPage = () => {\n  const projects = useProjects(); // Consommation agnostique\n  return (\n    <div className=\"grid\">\n      {projects.map(p => <ProjectCard key={p.id} data={p} />)}\n    </div>\n  );\n};\n```\n\n### Gestion des Animations (Canvas)\nPour éviter les problèmes de performance de l'ancien site (reflows permanents), les animations Canvas (Grid, Stars) sont gérées par un `AnimationEngine`.\n\n-   **VisualComponent (React)** : Crée une balise `<canvas ref={canvasRef} />`.\n-   **AnimationService (TS Class)** : Reçoit la ref du canvas, initialise le contexte 2D/WebGL, et gère la `requestAnimationFrame` en dehors du cycle de rendu React pour maximiser les FPS (60fps target).\n\n---\n\n## 5. Automatisation & DevOps\n\nPour garantir un niveau \"Senior\", le projet intègre des pipelines de qualité et de déploiement.\n\n### GitHub Actions (CI/CD)\nFichier : `.github/workflows/main.yml`\n\n1.  **Job: Quality Check** (sur Pull Request)\n    -   Installation des dépendances.\n    -   **Linting** : ESLint (Qualité du code).\n    -   **Type Checking** : `tsc --noEmit` (Vérification stricte des types).\n    -   **Format** : Prettier check.\n\n2.  **Job: Build & Deploy** (sur Push main)\n    -   Build Vite (`npm run build`).\n    -   Déploiement automatique sur **GitHub Pages** (via `actions/deploy-pages`).\n\n### Docker (Conteneurisation)\nBien que GitHub Pages soit statique, fournir une configuration Docker démontre la compétence \"Full Stack\" et permet de tester le build de production en local.\n\n**Dockerfile (Multi-stage build) :**\n1.  **Build Stage** : Node.js image. Installe deps + Build l'app.\n2.  **Production Stage** : Nginx Alpine image. Copie les fichiers buildés (`/dist`) vers `/usr/share/nginx/html`. Copie un `nginx.conf` optimisé (Gzip, Caching headers).\n\n---\n\n## 6. Migration des Features Legacy\n\n| Ancien Fichier | Nouveau Module | Stratégie |\n| :--- | :--- | :--- |\n| `aboutMe.js` (convecteur) | `features/about/TimeTravelParams.tsx` | Remplacer la manipulation DOM directe par React State (`activeStep`). |\n| `grid.js` | `features/visuals/RetroGrid.ts` | Refactoriser en classe TS, détacher du scope global. |\n| `orbit.js` | `features/home/OrbitMenu.tsx` | Utiliser CSS Transform + React Spring pour fluidifier le mouvement. |\n| `searching.js` (Pills) | `features/search/MatrixMode.tsx` | Gérer l'état \"Matrix/Glitch\" via Context global. |\n| `loading.html` (iframe) | `shared/components/PageTransition.tsx` | Remplacer par `AnimatePresence` (Framer Motion) entre les routes. |\n"
